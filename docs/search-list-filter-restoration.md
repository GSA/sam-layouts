# Search-list filter restoration contract

`SearchListLayoutComponent` retains a restored page only while the effective Formly filter still represents the restored filter. A changed filter goes to page 1 **on the first emission too**; there is no unconditional first-emission grace period. Later equivalent emissions must not lose the page. The observable contract is the public `page.pageNumber`, the Formly model update, and (when enabled) search requests—not private restoration flags.

The URL path uses query keys flattened through `URLSearchParams`, then `qs.stringify(..., {skipNulls: true, encode: false})` and `qs.parse` with the component's boolean decoder. The 20/21 distinction is **observed through that real history restoration path**: a 20-element `sfm.values` is an array, while 21 indexed values are restored as an index-keyed object (`qs` default array limit). Both compare equivalent to Formly's 20/21-element arrays and retain page 3; appending a slot resets to page 1. This is not a claim based solely on the shape of the original query string.

URL-shaped equivalence serializes leaf values (e.g. URL string `"0"` equals Formly number `0`, URL `"false"` equals Formly boolean `false`), omits nullish object fields, empty arrays and recursively empty object groups, but retains positional array slots. Class controls with enumerable fields follow their URL representation; see the existing `Selection` cases. Results-model restoration is **typed**: `0` differs from `"0"`, `[null]` differs from `[{}]` (including on the first changed service emission), and `false`/`0` are not discarded. An empty/null results filter publishes `{}` as its effective Formly model (`publishes an empty effective model when restoring a null results filter`). A results model is snapshotted: external mutations and in-place Formly mutations must not silently preserve the old page (`does not retain consumer-owned references…`, `resets after an in-place mutation…`, `resets the restored page after a Date is mutated…`).

Page retention and request deduplication are **different contracts**. The `requests restored $source page on first equivalent emission only` cases capture `getData` via public Formly communication: initial URL requests page 3 and popstate requests page 4 on their first equivalent emission, with no second request for a repeated equivalent emission. A suppressed equivalent communication emission should leave the page alone, but restoration of a different model must still allow a previously emitted filter to be applied (`applies an earlier Formly filter after restoring a different results page`). A newly restored results model issues a page-3 request after an earlier request settles; a duplicate does not issue another (`applies the first restored Formly filter after an earlier request settles`). Excluding a filter field may suppress a request while a changed filter still resets the page (`retains excluded-field request suppression while resetting a changed filter page`). Page-only tests disable API calls. These specs inspect restoration, requests, and page state; they do **not** test a browser back/forward navigation round-trip.
